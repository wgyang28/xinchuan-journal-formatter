## 输入文件要求

在使用任一期刊 Skill 之前，请确认你的 `.docx` 满足以下条件：

**1. 论文要素齐全**

应包含：标题、作者（投稿时可匿名）、内容提要/摘要、关键词、正文、脚注。缺少要素不影响脚本运行，但会在修改报告中标记提醒。

**2. 引文以脚注形式标注**

- 所有文献引用须已置于**页下脚注**（Word 的脚注功能），格式不限——APA、GB/T 7714、MLA、中文自定义格式均可
- **每条脚注的文献要素必须齐全**：作者、题名、出版信息（出版地/出版者/年份）、页码（著作类）。要素缺失的条目，脚本不会补全，只在报告中标记待人工处理
- 括注（正文夹注，如"（作者，年份）"）可以存在，脚本会尝试将其与已有脚注配对后删除，或转换为新脚注；但括注本身也需要能对应到完整的文献信息

**3. 标题使用 Word 内置标题样式**

各级标题须在 Word 中明确设为对应的标题级别：

| 期刊标题层级 | 对应 Word 样式 |
|-------------|----------------|
| 一级标题（`一、……`） | 标题 1（Heading 1） |
| 二级标题（`（一）……`） | 标题 2（Heading 2） |
| 三级标题（`1．……`） | 标题 3（Heading 3） |

> 未套用 Word 标题样式的段落，脚本会尝试通过前缀正则识别（如`一、`、`（一）`），但识别准确率低于显式样式，建议投稿前在 Word 中统一套用。

## 工作原理

采用**代码 + Claude 判断**的混合策略：

1. **结构抽取**（脚本）：读取 `.docx`，打印全部脚注、括注、标题层级、前置信息
2. **引文映射**（Claude 判断）：逐条把各式引文映射到目标格式，生成判断表 `citation_map.py`
3. **写回 + 报告**（脚本）：机械格式（字体/行距/页边距/脚注编号）+ 引文写回，产出新 `.docx` 和 Markdown 修改报告

> **铁律**：转换时只允许重排已有文献信息的顺序与标点，**严禁新增、补全或推断任何文献内容**（作者、年份、页码、出版社等）。信息缺失一律在修改报告中标记待人工复核，绝不擅自猜测。

## 推荐使用的模型

本 Skill 的核心步骤（引文映射、格式判断）依赖 Claude 的推理能力。**强烈建议使用能力较强的模型**，否则引文映射准确率会明显下降。

**推荐使用 Claude Opus 系列**，或其他供应商中具备同等深度推理能力的模型。引文映射步骤对模型推理能力要求较高，使用轻量模型会明显增加误判率。

在 Claude Code 中切换模型：

```bash
# 查看当前模型
/model

# 切换为 Opus（示例，具体模型名称以当前版本为准）
/model claude-opus-4
```

> 使用 Sonnet 或更轻量的模型时，脚本仍可运行，但引文类型误判率会升高，建议在修改报告中更仔细地核查「待人工复核清单」。

## ⚠️ 免责声明：本工具只能完成约 90% 的工作

本 Skill 的目标是**大幅减少格式调整的重复劳动**，而非完全替代人工校对。以下诚实说明其能力边界：

**能可靠完成（~90%）**

- 页面排版：A4 页边距、正文字体字号、固定行距、段前段后、首行缩进
- 标题层级：按级别套用黑体分级字号
- 脚注编号：①②③ 每页重排
- 摘要标签：「摘要」→「内容提要」
- 引文体例转换：APA / MLA / GB/T 7714 / Vancouver / 中文混排统一为本刊脚注格式
- 外文题名斜体、篇名引号、`p.`/`pp.` 用法
- 括注删除（与同段脚注重复者）；田野/访谈资料等说明性括注保留
- 脚注序号位置：从句末标点之后移至之前
- 完整性校验：脚注 ↔ 正文引用一一对应

**无法保证、需研究者亲自校对（~10%）**

1. **引文映射可能有误判**。Claude 逐条判断引文类型并生成映射表，偶尔可能：
   - 误判文献类型（期刊析出 vs 文集析出、专著 vs 编著）
   - 中文标点（全角/半角逗号、书名号配对被中文引号干扰）细微偏差
   - 多文献共用一个脚注序号时，分隔符处理不当
2. **信息缺失的文献不会补全**。缺出版地、出版者、年份的条目在报告中标记，但不会自动修正。比如 `Auty, R. M. (1993)` 缺出版地，报告会提醒，但脚注里仍缺。
3. **Word / WPS 渲染差异**：
   - WPS 个别版本对 ①②③ 编号兼容差，可能回退为 1,2,3，需手动重设
   - 固定行距 15.6pt + 五号字 ≈ 每页 38 行，但不同操作系统/打印机驱动下实际行数可能有 ±1 行偏差
   - 脚注段前段后为 0、单倍行距的设置，在 WPS 中可能显示略有不同
4. **图表跨页**：脚本不处理，需手动检查
5. **「同注X」序号**：X 是当页显示序号，依赖 Word 分页结果，脚本不计算——重复引用以完整脚注落地，研究者需手动改为「同注X，第Y页」
6. **英文摘要/标题**：不会自动翻译生成，需作者另附
7. **匿名评审**：脚本不识别正文中可能暴露作者身份的词句（「笔者」「拙文」「本人」「本课题组」等），需自行排查
8. **脚注编号在正文中的显示**：个别情况下 ①②③ 可能显示为空白方框或乱码，取决于系统字体

### 拿到修订版后，请做以下检查

1. 在 Word/WPS 中打开输出文件，逐页浏览：
   - 脚注编号是否显示为 ①②③（而非 1,2,3）
   - 脚注是否每页从 ① 重新编号
   - 图表是否跨页
2. 对照《修改报告》第四节「待人工复核清单」，逐条确认并处理
3. 重点抽查 3-5 条改写后的脚注，核对格式是否准确
4. 通读全文，检查正文删除括注后句子是否通顺、引述关系是否清楚
5. 确认文末资助说明仅保留一项，且正文无暴露作者身份的信息

> **一句话**：本 Skill 帮你省掉 90% 的格式苦力，但最后的 10%——判断、核对、确认——仍然是研究者自己的责任。投稿前请务必通读一遍。

## 前置依赖

- [Claude Code](https://claude.ai/code)（CLI 版）
- Python 3.9+
- `pip install python-docx lxml`

## 安装

**第一步：克隆仓库**

```bash
git clone https://github.com/wgyang28/xinchuan-journal-formatter.git
cd xinchuan-journal-formatter
```

**第二步：安装所需期刊的 Skill**

按需选择，每本期刊独立安装：

```bash
# 《新闻与传播研究》
ln -s "$(pwd)/xwycbyj-formatter" ~/.claude/skills/xwycbyj-formatter
```

> 符号链接方式推荐：仓库执行 `git pull` 后，本地 skill 自动同步最新版本，无需重新复制。

## 新增期刊

1. 在仓库根目录新建子目录 `<期刊缩写>-formatter/`
2. 参照 `xwycbyj-formatter/` 的结构，替换 `references/` 里的规范文件和 `format_config.json`
3. 在子目录内新建 `README.md`，写明安装方法与触发词
4. 更新本 README 的期刊列表
