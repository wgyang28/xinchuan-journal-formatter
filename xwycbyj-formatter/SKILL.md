# 《新闻与传播研究》格式调整 Skill

把写好的论文 `.docx` 调整为《新闻与传播研究》投稿格式：**机械格式**（版面/字体/标题/脚注编号）用脚本可靠完成，**引文映射**（各式引文 → 本刊脚注体例）由 Claude 依规范判断、脚本写回，最后产出**新文件 + 修改报告**。

## 🔒 铁律（每次执行都必须遵守，且写入报告）

> **转换时只允许重排已有文献信息的顺序与标点，严禁新增、补全或推断任何文献内容（作者、年份、页码、出版社、出版地等）。凡信息缺失或无法确定的，一律在《修改报告》中标记待人工复核，绝不擅自猜测。**

派生原则：
- ❌ 不改正文实质内容（论述文字、引文原文）；不捏造文献数据。
- ✅ 可删除与脚注重复的正文括注；可调整脚注内既有信息的顺序/标点/国籍标注/页码格式；可把括注里已有的页码搬入对应脚注（属"搬运既有信息"）。
- 输出**绝不覆盖原文件**：新文件名 `<原名>_新传研究投稿版.docx`，报告 `<原名>_新传研究投稿版_修改报告.md`。

## 唯一权威依据（source of truth）

`references/新闻与传播研究_格式与注释规范.md` —— **每次处理前先完整读取**，引文体例与收尾清单一律以它为准。期刊改版时只改该文件与 `references/format_config.json`，不改脚本。

机械格式参数（字体/字号/行距/段前段后/页边距/标题分级/脚注编号）全部在 `references/format_config.json`，不写死进代码。

## 文件结构

```
references/
  新闻与传播研究_格式与注释规范.md   # 引文体例 + 收尾自检清单（权威依据）
  format_config.json                # 版面/字体/字号（可编辑，期刊改版改这里）
scripts/
  extract_structure.py   # ① 只读抽取：标题/前置/脚注/括注/文末参考文献 → 打印摘要
  citation_map.py        # ② 引文映射判断表（针对每篇稿，由 Claude 生成/覆盖）
  apply_all.py           # ③ 一键执行：机械格式→引文写回→修改报告（只产 docx + 报告.md）
  apply_format.py        # 机械格式模块（页面/字体/标题/脚注编号/摘要标签，读 config）
  apply_citations.py     # 引文写回模块（改写脚注、删/转括注、序号位置、完整性校验）
  footnote_ops.py        # 稳健脚注 XML 库：建/删/改脚注、插引用、删括注、移序号、校验
  build_report.py        # 修改报告渲染模块
```

> **不产生 JSON 中间文件**：apply_format / apply_citations / build_report 均为模块，数据走内存，由 apply_all 串起，**只落地两个文件**：`<原名>_新传研究投稿版.docx` 和 `..._修改报告.md`。

## 执行流程

### ⚠️ 操作前必读
1. **关闭 Word/WPS**：文件在编辑器中打开时，脚本写入可能被覆盖。
2. **OneDrive/iCloud 同步**：脚本写入后等同步完成（Finder 无旋转图标）再用 Word 打开验证；必要时复制到非云盘目录验证。
3. 看 apply_all 末尾的完整性校验结果（PASS/❌）。

### Step 0：读规范
完整读取 `references/新闻与传播研究_格式与注释规范.md`。确认输入 `.docx` 路径；未提供则询问。

### Step 1：抽取结构（只读，打印到屏幕，不产文件）
```bash
python3 scripts/extract_structure.py "<输入.docx>"
```
打印：标题层级、前置部分（内容提要/关键词/英文）、全部脚注文本、正文括注线索（含"同段是否已有脚注"标记）、文末参考文献。**据此判断引文现状**（脚注/括注/APA/GB…混用情况）。

### Step 2：生成引文映射判断表（Claude 核心判断）
读 Step 1 输出 + 规范，**为本篇稿写 `scripts/citation_map.py`**（覆盖示例）。逐条把每个脚注/括注映射到目标格式：
- `FOOTNOTE_TARGETS[fn_id] = [(文本, 是否斜体), ...]` —— 外文题名段 `True` 即斜体。
- `INTEXT_ACTIONS` —— 每个括注的动作：`delete`（与同段脚注重复）/ `to_footnote`（重复引用等需新建脚注者，给 `fn_text` 或 `fn_segments`）/ `keep`（田野笔记、访谈资料等说明性括注，保留原样）/ `keep_flag`（信息缺失，保留待补）。
- `DELETE_FN` —— 空脚注等。
- `FLAGS` —— 所有待人工复核项（分类：匿名/缺信息/冲突/重复/人名/格式）。

**判断要点（对照规范）：**
| 现象 | 处理 |
|------|------|
| 括注后紧跟脚注标记（并存） | 删括注，保脚注；括注内页码搬入脚注 |
| 田野/访谈/资料括注 | 保留括注（属说明性标注，非文献引用，不转脚注） |
| 学术括注无脚注、无文末参考文献 | **不编造**，`keep_flag` + 报告标注待补 |
| 重复引用（同文献再现，原位无脚注） | 新建完整重复脚注（不丢引用）+ 报告建议改"同注X，第Y页"（当页序号需 Word 分页后人工填） |
| 期刊脚注带了页码 | 去页码（期刊不带页码） |
| 外国作者无国籍 | `〔美〕`（方括号，非圆括号） |
| 英文专著/文集析出 | 名前姓后；题名斜体 |
| 英文期刊析出/译著 | 姓前名后；篇名英文引号、刊名斜体；`p.`/`pp.` |
| 中文译著 | 书名后加"，译者名译"，多译者顿号分隔 |

在 `FLAGS` 里同时纳入 Step 3 的自检结果：匿名（"笔者""拙文"、作者本人姓名、自引会暴露身份）、外国人名（首现须"汉译（原名）"）、资助项目（置于文末、只留一项）。详见 `references/新闻与传播研究_格式与注释规范.md` 的 6 大类模板。

### Step 3：一键执行（机械格式 + 引文写回 + 修改报告）
```bash
python3 scripts/apply_all.py "<输入.docx>"
```
一次性完成、**只产出 docx + 报告.md，无任何 JSON**：
- 机械格式：A4 页边距（每页≈38行×41字）、正文宋体/TNR 五号、固定行距 15.6pt、**段前段后 0**、首行缩进 2 字；各级标题黑体分级字号；脚注小五、**段前段后 0、单倍行距**、编号 ①②③ 每页重排；**摘要标签自动改为「内容提要」**（仅标签，不动正文）。
  （脚注段前段后/行距由 `footnote_ops.set_footnote_para_spacing` 直接写 `footnotes.xml`——python-docx 对脚注段 `space_before=0` 不稳定，故 before/行单位/自动间距统一在此落属性。）
- 引文写回：按 citation_map 改写脚注、删/转/保留括注；**统一脚注序号位置**——句末标点之后的序号移到标点之前（`……研究①。` 而非 `……研究。①`；`footnote_ops.fix_fnref_punctuation` 处理 `。！？，；：`，引号/括号/书名号不动）。
- 末尾打印完整性校验（脚注↔正文引用一一对应、ID 连续）。**必须 PASS ✅**；若 ❌ 看告警定位。
- **英文标题/作者/摘要/关键词不自动生成**（凭空翻译=创造内容，违铁律），仅在报告提醒作者另附。

### Step 4：向用户交付
报告输出文件路径 + 修改报告路径，口头摘要：完成的格式/引文改动、待复核要点（尤其匿名与缺信息项）、需在 Word 手动确认的事项（脚注编号显示、图表跨页）。

## 已实测验证

`footnote_ops.py selftest <docx>` 自测新建脚注+插引用+往返复读，对样例稿 PASS。整条流水线已在真实混杂稿（49 脚注含 APA/MLA/GB/Vancouver/中文混排 + 54 括注）跑通：49→72 脚注、引用一一对应、ID 连续、孤立括号 0、摘要标签→内容提要、句末序号 7 处归位、Word 可正常打开（无"不可读取的内容"、脚注每页重排）。

## 注意事项
- **脚注编号 ①②③ 每页重排** 通过 `settings.xml/w:footnotePr` 的 `w:numFmt`+`w:numRestart` 设置。⚠️ **schema 顺序坑**：`w:footnotePr` 子元素必须 `pos? → numFmt? → numStart? → numRestart? → footnote*`；`numFmt/numRestart` 若被追加到 `w:footnote`（分隔符引用 -1/0）之后，**Word 会报"不可读取的内容"并忽略每页重排，而 WPS 宽松不报**。apply_format 已把它们插到 footnote 引用之前。
- **删脚注须同步清 settings.xml**：`w:footnotePr/w:footnote[@id]` 若引用了已删除的脚注 id，会成悬空引用、触发 Word"不可读取的内容"。footnote_ops.delete_footnote 已一并清理；空白分隔类脚注（如本例 fn1）不建议脚本删，留 Word 手动删。
- WPS 个别版本对 `decimalEnclosedCircle` 兼容差会回退为 1,2,3 → 手动在 WPS：引用→脚注→编号格式 ①②③、每页重置。
- "同注X" 的 X 是**当页显示序号**，依赖分页，脚本不计算 → 重复引用先以完整脚注落地，报告提示人工改同注。
- 每行≈41字由字号(10.5pt)+版心宽(14.66cm)决定，不额外调字距；最终行数以 Word 重排为准。
- 图表跨页脚本不处理，需 Word 手动检查。
- 写回后用 `extract_structure.py` 复跑可复核残留括注是否仅剩田野/访谈说明性括注与"待补"项。

## 附录：脚注 XML 要点（footnote_ops 已封装）
- `.docx` 是 ZIP：`word/document.xml`（正文+引用标记）、`word/footnotes.xml`（脚注）、`word/settings.xml`（脚注编号）。
- python-docx 不能干净新建脚注 → 本库直接操作 XML，**克隆现有脚注/引用节点作模板**新建，避免硬编码样式 id（ae/af0 随文档而变）。
- 删括注**只清 `w:t` 文本、不删 run**，保住内嵌的 `w:footnoteReference`。
- 新脚注 id 取 max+1；写回前按 id 排序（WPS 兼容）。
- 完整性校验：正文引用 id 集合 == 脚注 id 集合，且 id 连续无断号。
